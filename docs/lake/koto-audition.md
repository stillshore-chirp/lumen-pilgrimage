# 箏の比較試聴

このページは、所有者が研究中の箏音源を同じ条件で比較し、所見を残すための開発用試聴室の使い方と実装契約をまとめます。音源のモデル・採否・測定方法は、[箏の測定設計](koto-measurements.md)を参照してください。

## 開く

リポジトリの依存を準備し、比較音声を `artifacts/koto-study/` に生成した後、`npm run dev` を起動して表示されたローカルURLの `/tools/koto-audition.html` を開きます。通常の本番ビルドはこのHTMLを入口に含めず、比較WAVも `public/` には置きません。音声がまだ生成されていなければ、読み込み失敗の案内と再読み込みボタンが出ます。

別の比較データを使うときは、同じサーバー上のパスを `?manifest=/artifacts/別の比較/manifest.json` に指定します。外部オリジン、認証情報付きURL、データURL、リダイレクトは読み込みません。音声・図の相対パスはmanifestの場所から解決します。Vite開発サーバー以外へ比較データを配布するときは、素材ごとの権利・配布条件を先に確認してください。

## 比較する

1. 方式と演奏・奏法を選びます。方式を選ぶと、現在の演奏が使える場合は維持し、音声がない場合はその方式で再生できる演奏へ切り替えて案内します。配布候補はカードを押すだけで「39秒の独自曲」を再生できます。方式の表示はmanifestの状態と実際のclipに従い、未適格・不在の方式を架空の音声で補いません。暫定素材の制約は方式カードから開いて確認できます。
   未対応条件を調べる場合は「演奏・奏法」から「この方式の音声なし」と付いた項目も選べます。このときは再生ボタンの直下に理由と復帰手順を表示し、「再生できる演奏に戻す」で戻れます。
2. 「音量整合を使う」を選びます。単音・奏法・短旋律では中音通常強度の共通ゲインを使い、方式内の弱強の差を保ちます。全曲は39秒のRMSを別に整合します。RMSの一致は聴感上の同音量を保証しません。
3. 「乾音」または「湖畔・天井12スピーカー」を選びます。湖畔では中央・西窓・東窓・後方と、湖・西・後方・東の向きを選べます。眼高は1.65 mです。
4. 低めの初期音量20%から再生します。「停止」「先頭から」「繰り返し再生」と出力音量を使えます。方式・奏法・経路・整合・位置・向きの変更は再生を止め、操作後の再生ボタンから先頭を聴きます。
5. 波形とスペクトルは乾音の図です。整合のON/OFFは図にも反映しますが、出力音量・ピーク保護・空間処理の結果は含みません。スペクトルは全曲平均ではなく、生成器が記録した `windowSeconds` の窓です。ピーク・RMSと全測定値は数値でも確認できます。客観測定の不合格と、音高を測れなかった `null` は条件欄に表示し、0 Hzや合格へ置き換えません。
6. 実際に人間が聴いた条件にだけチェックを入れ、判定・機器・所見を入力します。「比較条件とメモを書き出す」でJSONを端末へ保存します。入力がない聴取条件は「未評価」です。再生成功や数値から聴感の判定を作りません。

条件を戻すとその条件のメモが戻ります。メモはタブ内のメモリーにのみ保持し、ページを閉じると消えます。書き出しはブラウザーのダウンロード機能を使い、サーバーへ送信しません。「湖畔の広間で聴く」は通常の `?world=lake` へ移動します。移動前に必要なメモを書き出します。

## 信号・資源・入力の契約

[実装](../../src/dev/kotoAudition.ts)と[画面のスタイル](../../src/dev/kotoAudition.css)は独立した開発用入口から読み込みます。通常探索の `main.ts` は参照しません。新しい依存や外部フォントも追加しません。

| 境界 | 処理と確認すること |
| --- | --- |
| 比較データ | `schemaVersion: 1`、mono、数値・件数・参照の整合、重複IDと同一方式/条件の重複、音声・図URLの同一オリジンを読み込み境界で検査します。JSONをDOMのHTMLとして挿入しません。 |
| 乾音 | WAV → 開始/停止フェード・raw保護 → 出力音量 → 出力。音量整合ONは事前整合WAVを読み込みます。 |
| 湖畔 | WAV → 開始/停止フェード・raw保護 → 本番共通の12スピーカー → 本番共通マスター係数 × 出力音量 → 本番共通の最終リミッター。環境音や歩行音は含みません。 |
| raw保護 | 整合OFFのfloat32 WAVは振幅1を超えることがあります。デコード後の実ピークから、最大−3 dBFSへ減衰するゲインを求めます。事前測定からの予測値と、実デコード後のゲインを条件に表示・保存します。純rawを無減衰で出力する操作は設けません。 |
| 再生の寿命 | ユーザーの再生操作でAudioContextを作成・再開します。停止時は12 msのフェードを予約し、前のsourceの終了または切断を待って次を開始します。音量操作は時定数15 msで平滑化します。 |
| キャンセル | 方式等の切替・停止でfetchを中断し、世代番号が変わったdecode完了を無効にします。遅れた処理から再生しません。 |
| ページ移動 | `pagehide` でsource、フェード中source、スピーカー、最終出力ノードとAudioContextを解放します。BFCacheから戻る場合、次の再生操作で新しいContextを作れます。 |
| 評価 | 条件ID、元音声パス、ゲイン、音量、位置・眼高・向き、ループ設定、旧音源の版、未実施項目とユーザー入力をJSONへ保存します。人間聴取チェックを外すと判定は未評価へ戻ります。 |

音源位置と距離ゲインは[共用スピーカー経路](../../src/coast/world/lake/lakeKotoSpeakers.ts)、マスターは[湖畔音響](../../src/coast/world/lake/lakeAudio.ts)、最終段は[探索出力](../../src/coast/explorationOutput.ts)をそのまま使います。聴取点のX/Zは[広間の寸法と開始点](../../src/coast/world/lake/lakeLayout.ts)から求め、向きはWeb Audioのlistenerへ設定します。比較WAVの入力自体は通常演奏から独立しています。

## 設計根拠と検証

[W3C Web Audio 1.0 §1.7.2](https://www.w3.org/TR/webaudio-1.0/#dom-audioscheduledsourcenode-stop)の時刻指定停止と[§1.6.2](https://www.w3.org/TR/webaudio-1.0/#dom-audioparam-linearramptovalueattime)の連続ゲイン変化を、source切替の順序と短いフェードへ適用しました。12 msと15 msは比較操作のための実装上の値であり、箏の自然さを示す測定値ではありません。[§1.11](https://www.w3.org/TR/webaudio-1.0/#AudioListener)の位置・前方・上方ベクトルは、本番と同じ座標で向きを設定する根拠です。

[WAIのフォームラベル](https://www.w3.org/WAI/tutorials/forms/labels/)と[見出し階層](https://www.w3.org/WAI/tutorials/page-structure/headings/)をnative input・select・labelとh1/h2へ適用しました。UI/UXスキルの検索結果から、既存ブランドの深緑と淡いミント、明瞭な選択枠、キーボードfocus、数値の代替表示を採用しました。検索が返した販売用のヒーローや推薦文の構成は、この比較用途に合わないため採用していません。

[ブラウザー試験](../../scripts/koto-audition-browser.test.mjs)を `node --test scripts/koto-audition-browser.test.mjs` で実行します。PlaywrightのChromiumを使い、Vite開発サーバーをloopbackに起動します。`KOTO_AUDITION_SCREENSHOTS=/absolute/output` を付けると1440px/375pxの画面と検証条件を保存します。

試験では合成WAVを使い、実際のWeb Audio出力、単一source、停止・ループ・先頭再生、整合OFFの保護、12スピーカー、位置と向き、遅延読み込みのキャンセル、利用できない方式、未評価のJSON書き出し、条件を戻したメモ、図のエラー、キーボードfocus、375pxと横長812pxでの収まりを確認します。合成音での機能試験は、研究音源の聴感・機器出力・VR実機の検証を代替しません。

`KOTO_STUDY_MANIFEST=/absolute/path/manifest.json` を付けると、生成済みの実音源と図を読み、乾音と湖畔の実Web Audio出力を追加確認します。このときだけ、指定したmanifestのディレクトリを試験用Viteサーバーの読み出し対象に加えます。研究生成器を同時に実行せず、固定したスナップショットを使います。実音源の再生も、人間による試聴済みの記録には変換しません。

既に稼働している試聴室を直接確認するときは、`KOTO_AUDITION_ORIGIN=http://127.0.0.1:4191` と、そのサーバーが配信するmanifestの実ファイルを `KOTO_STUDY_MANIFEST` に指定します。新しいサーバーは起動せず、実サーバーの `/artifacts/koto-study/manifest.json` と指定ファイルのhashが一致すること、初期選択の再生、配布候補のカードだけを押したときの39秒への切り替え、実出力を確認します。
