# 十三弦箏音源の設計と評価

湖畔の広間の39秒の独自曲を対象に、音色モデル、演奏制御、空間再生を別々に評価する。要求と工程の記録は[研究開発計画](../../plans/koto-instrument-rd.md)と[Issue #275](https://github.com/stillshore-chirp/lumen-pilgrimage/issues/275)に置く。本ページは採用設計と実装・検証への対応の正本とする。研究中の方式・素材や、未実施の人間の評価を完成品質の証拠にしない。

## 現行音源の分析

比較基準は[保存した旧実装](../../scripts/fixtures/lakeKotoLegacy.ts)。24 kHzで18倍音、6つの独立した胴の正弦波、22 msのノイズ、最大2.9秒の音を生成し、39秒全体のピークを0.76へそろえていた。押し手は48サンプル単位の発振周波数変更で表し、弦の張力や胴の状態とは独立だった。単音には曲全体の正規化が掛からない。

これらはコードの事実であり、電子的な印象や余韻の不足をどれほど生むかは別の検証課題である。サンプリング周波数を上げるだけでは励振・エネルギー伝達・奏法の不足は解消しない。既存の天井再生は同じmono信号を12個のHRTFへ配るPAの近似であり、楽器自体の胴の放射や広間の残響と同一ではない。

## 比較と採用の判定

純粋な物理合成、録音サンプル、ハイブリッドの優劣は事前に決めない。実際にレンダーした出力と測定を比較し、サンプルが不足する方式・音域は利用不能として理由を表示する。異なる生成方式を混ぜた結果を純sampleと表示しない。採用可能な録音が見つからない場合も物理モデルの研究・修正を続ける。

方式選定の根拠には、実物らしい音色の評価に加え、音域・強弱・奏法、物理/信号の妥当性、計算負荷、配布量、再現性、権利・倫理と保守を含める。人間の聴感が未実施なら、客観比較による技術上の選択と、最終的な音質の合否を分けて記録する。

### 暫定的な技術選択

最初の技術候補はハイブリッドとした。これは「人間が自然な箏と評価した」という決定ではない。16条件・4方式の比較に、同梱する96 kHz内部生成版の全曲を加えた64音声を作成した。数値と不合格条件は[測定正本](koto-measurements.md)を参照する。後述の所有者の聴感では箏の楽器同定が不成立だったため、現在は音色の再設計対象であり、最終採用の合格候補ではない。

| 方式 | 観測した成立範囲 | 今回の判断 |
| --- | --- | --- |
| 旧加算合成 | 基音・押し手・静かなループは既に成立。独立胴振動、2.9秒の音、消音未対応 | 比較基準として保存。音高が合うだけでは自然さを示さない |
| 改良物理 | 弦・胴の双方向連成、接触初期条件、非調和性と周波数別損失、張力変化、消音。数値安定・周波数・減衰・収束を検証 | 全音域の基盤として採用。実測橋アドミタンス等の未同定値は仮定として残す |
| 純サンプル | 5加工単音、転調±5半音。A3/B♭3は未対応、短い録音で押し手2件・消音1件の検証が不成立 | 全曲には不採用。失敗音・理由を比較画面に保持し、別方式の成功と混ぜない |
| ハイブリッド | 実録音の3.5 kHz以上の短いアタックと物理の基本音・胴・余韻を相補的に接続。150 ms以降は物理と同一。48音中4音は録音不在を明示して物理のみ | 技術候補。実録の手掛かりを残しつつ全曲・押し手・消音を成立させる。位相/帯域接続を測定したが、聴感上の優越は未判定 |

内部生成は96 kHz、配布は48 kHz/mono/24-bit PCM、39秒とする。数値改良後の880 Hz単音の未整合波形差は48/96 kHzで−26.50 dB、96/192 kHzで−38.88 dBとなった。時間ずれを後から合わせた値を受け入れに使わず、分離診断と区別する。オフラインの約2倍の生成負荷を許容して離散化精度を上げ、通常再生は完成PCMをロードする。これは実録との一致や聴感を証明しない。

配布音は全曲に一つの固定gainを適用し、RMS −24 dBFS、sample peak上限−3 dBFSを設計値とした。実出力はRMS −24.000、peak −3.707 dBFS。量子化はseed固定のTPDFを用い、24-bit化の実誤差RMSは−144.50 dBFSだった。圧縮プレビュー由来の情報を24-bit化で復元したとは扱わない。[生成記録](../../assets/lake-audio/production.json)に入力hash、元出典、配布hash、性能と未評価を残す。

## 再生成と比較の手順

Node.js 22.23.4とリポジトリの依存関係を用意する。配布音と5加工単音は既に同梱しており、通常再生に録音配布サイトへの通信は不要。元の長いプレビューを得られなくても、同梱したhash固定の加工単音から音源を生成できる。

```sh
# 96 kHzで全曲を生成し48 kHz/24-bitへ変換。オフラインで約90秒。
npm run prepare:koto

# 旧新・方式・奏法・全曲の比較音声と測定JSONを生成。
npm run research:koto

# 開発用画面。表示されたローカルURLの /tools/koto-audition.html を開く。
npm run audition:koto
```

[生成CLI](../../scripts/prepare-koto-performance.mjs)は元出典の採用状態、入力hash、生成中の変更、有限値とheadroomを確認し、[配布WAV](../../public/lake-audio/koto-performance.wav)と生成記録を出力する。[比較CLI](../../scripts/koto-analysis.mjs)はraw float・音量整合PCM・波形/スペクトル・入力snapshot・未対応を `artifacts/koto-study/` へ出す。この比較音声群と試聴画面は通常のVite配布入口に含まれない。原録音から5単音を再作成する手順は[加工正本](koto-sample-processing.md)に分ける。

## 本番への統合と空間の近似

[ロード](../../src/coast/world/lake/lakeKotoAsset.ts)は初回の再生操作で同梱WAVを取得し、decodeしたmono bufferを広間の寿命で再利用する。[再生](../../src/coast/world/lake/lakeKoto.ts)はユーザー操作と非同期の世代を照合し、停止・取消・再試行・切替・破棄の後に古い音を再生しない。native decode自体は中断できないため、停止中のdecodeは重複起動せず再利用し、破棄後の結果は捨てる。[通常/VRの操作](../../src/coast/LakeEnvironmentPanel.ts)は準備中にも中止できる。

[12基の共有経路](../../src/coast/world/lake/lakeKotoSpeakers.ts)は、描画と同じm座標、距離weight、向き付きHRTF、広間のmasterと最終出力段を、本番と試聴画面で共用する。[W3C Web Audio API 1.1の2026年9月22日版](https://www.w3.org/TR/2026/WD-webaudio-1.1-20260922/) §1.1.2、§1.9.5、§6.1/6.3.2のdecode、loop、listener・HRTFの条件を実装へ対応付けた。Pannerの距離減衰は0にして二重適用を避ける。

現状は同じmonoをcoherentに配るPAの近似であり、実スピーカーの周波数応答、伝搬時間、広間IRは未同定。短いIRを同じ条件で測り、方向固有のHRTF、12基の加算、最終段を分離した。中央の12基は最近傍1基との音量整合後に低域が約4.59 dB増え、高域は約2.99 dB減る条件があった。これは観測結果であり、方向の手掛かりを逆EQで消す根拠にはしない。乾音と最終経路を人間が比較して評価する。[空間診断スクリプト](../../scripts/koto-spatial-study.mjs)で条件を再現できる。

## 評価の境界

人間による試聴、耳元での音響較正、実機VRの確認を、自動波形解析・ブラウザー出力・模擬XRから推定して実施済みにしない。未実施の必須聴感評価は残す。実行可能な改良・測定・統合・検証は続け、最終報告では達成した技術条件、音質の未判定、残るモデル上の制約を区別する。

### 所有者による初回試聴と再設計の判断

2026-11-27、比較画面の「本番候補」を所有者が実際に再生した。対象は配布WAV SHA-256 `c73976efaa69ff309fdb66e765acad4e46c08770e850f0c3997ad78d909838c2`、64音声の比較manifest SHA-256 `14effbec0b2b10878a6b0372ddbd78f230a6734b70a1da1d446ab4b025da9f39`。所見は「少なくとも良くなっています」に続き、楽器の印象について「いや、ギターなんですよ。人間の直感的に。」だった。

これは所有者一名の実聴結果であり、機器・出力経路・音量・聴取時間は未記録。旧音源に対する改善の確認と、箏としての音色同定の未達を分けて保持する。「少しギター寄り」や全体合格へ弱めて読み替えない。現在の信号検査の成功は、箏の音として成立した証拠にならなかった。

同版を比較基準として保存し、まず実録単音・物理・ハイブリッドの全帯域アタックと減衰を分離する。150 ms以降を物理音だけへ戻す設計と、実測校正していない胴・放射係数を優先して診断する。因果関係を確認せず、根拠のないEQや全曲の反復生成で対応しない。生成記録の `technical-selection-human-listening-pending` は生成時点の状態であり、現在の聴感判定は本節とIssueに従う。

### 全帯域録音と実測拘束モードの限定試作

[試作生成器](../../scripts/koto-recorded-modal-study.mjs)は、加工単音のフェード前まで全帯域を保ち、信頼条件を満たす周波数・振幅・位相・減衰の独立モードだけへ35 msで接続する。延長は実録の持続音でも連成物理モデルでもなく、観測窓からの合成外挿である。周期波形のループは使わない。上限はfit窓の2倍かつ1秒という設計上の仮定とし、残差・位相・減衰が不適合なら延長しない。

319/452/640 Hzの根で延長を採用し、151/792 Hzは再構成残差0.778/0.986により棄却した。採用した根の残差は0.146〜0.303、接続時刻は加工単音内の0.178〜0.213/0.370〜0.405/0.241〜0.276秒、合成終端は0.561/1.037/0.750秒。中音と短旋律の一部に延長があり、低音・高音の試聴は全帯域の実録だけで延長なしとなる。5根全体や箏一般の校正成功とは呼ばない。

低中高の通常強度と短旋律の4条件を作り、既存の純sample/物理/旧hybrid各4本と計16本を比較する。最初150 msは純sampleとサンプル単位で同一、接続区間の最大隣接差は元録音以下、新単音の音高誤差最大5.809 cents、非有限値0、DC最大−109.7 dBFS、整合後peak最大−4.72 dBFSを確認した。これらは波形の検証であり、箏の同定・自然さの合格ではない。A3/B♭3不足、1強度層、短い圧縮録音への依存を保持する。

この比較を案内した後、所有者の所見は「安いエレキギター + テルミン + 琴 を３分割した印象」だった。対象manifestは `62e15d31efda74c4a9c8f4b3ce1c9ce990e2809bd5f5f86394e55472adfccb8f`。方式・条件ごとの選択履歴、機器・経路・音量・時間は未記録であり、どの成分が各印象を生んだかは断定しない。一つの箏としての一貫した音色が確認できていないため、この外挿方式は本番採用から外し、研究比較として保存する。全奏法・全39秒の聴感合格は未確認である。後続は実録のアタックから自然減衰までを保持する構成と、素材自体の一貫性を優先する。

先に `npm run research:koto` で既存比較を生成し、次を実行する。

```sh
node --experimental-transform-types scripts/koto-recorded-modal-study.mjs artifacts/koto-recorded-modal-trial artifacts/koto-study
```

試聴画面の `?manifest=/artifacts/koto-recorded-modal-trial/manifest.json` で別データを開く。元の64音声・配布WAVは変更しない。試作の回帰試験は既知の減衰モードの周波数/位相/減衰と将来波形、原音prefix保持、増大音の棄却、延長上限/静かな終端、実UIのmanifest/可視化契約と実ゲインの整合を確認する。

### 自然減衰だけを使う全録音の比較

取得済みSession 3の38.769–39.580秒、channel 0から240.270 Hzの単音候補を追加し、私有の6根bankで全録音方式を比較した。前の探索では強い第2倍音を基音と扱っていたが、240 Hz基音・721 Hz付近の奇数倍音・自己相関の240/480 Hz候補を照合して訂正した。元の2出典と同じ権利・録音主体の範囲で研究利用し、新たに十三弦個体や人間による混入確認を認定しない。公開素材bank・配布音は変更していない。

[生成器](../../scripts/koto-recording-performance-study.mjs)は、旧5根とこの単音の全帯域波形を自然な終端まで使う。13/13弦・48/48発音を最大3.526半音の移調でカバーし、周期ループ・modal外挿・物理fallbackは使わない。新規8条件と既存raw再利用9本の17音声を作成した。通常単音の音高誤差最大1.022 cents、39秒整合版のpeak−3.000/RMS−24.712/DC−107.75 dBFSを確認。rawのpeak+0.192 dBFSはfloatで保持し、UIでは保護ゲインを入れる。

これは不足音域の改善であり、奏法と音質の合格ではない。押し手2条件・消音1条件と、曲内4押し手の到達窓0.48–0.651秒では原録音が尽きる。末尾も最後の発音が約36.32秒で尽き、約2.68秒が無音となる。押し手の検証窓や合格基準は変えない。下位の演奏イベントの不足を全曲の判定へ引き継ぎ、全曲の`performancePress`を不合格として表示する。自然な反復、音色一貫性、全曲の聴感は未評価であり、本番採用しない。

再生成には先に既存比較を生成し、確認済みSession 3の48 kHz/stereo/PCM16 decodeを用意する。生成器は取得済み原本に対応するdecode hashを検査する。別の原音を同じ素材とみなさず、長い原録音を無断でリポジトリへ収録しない。

```sh
node --experimental-transform-types scripts/koto-recording-performance-study.mjs artifacts/koto-recording-performance-trial artifacts/koto-study /absolute/reviewed-source365242-decode.wav
```

`?manifest=/artifacts/koto-recording-performance-trial/manifest.json`で比較を開く。既存の17音声の版と、後続の判定metadata修正はhashで区別し、音声を変えていない場合も記録する。

### 長い混合区間の分離を採用しない判断

取得済みの長い452 Hz/605 Hz区間について、対象倍音を保護し、混入基音301/319/406 Hz等の非共有成分だけを局所同時最小二乗で減算した。公式SciPyの[`lstsq`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.linalg.lstsq.html)と[NOLA](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.check_NOLA.html)の条件を確認した私有実験で、外部実装の転載はない。長452 Hz区間の混入基音は約16.7/33.0/15.7 dB減ったが、対象の第2/4倍音と301 Hzの第3/6倍音は共有・近接して識別不能だった。

窓/周波数を変えた出力差は約2〜3%、対象の非共有帯域はほぼ保持された一方、既知真値の対照では発音前の前鳴りと別弦打音の残留が生じた。clean targetに対する相対誤差は25.5%であり、基音が減ったことだけを根拠にクリーン単音として採用しない。録音の長さ、同定可能性、変換の損傷、聴感を別々に確認する。

### 実行時の検証範囲

同梱WAVをnative AudioContext 48 kHzで156.13秒、39秒の4周分再生した。12基経路と最終出力段を使い、末端だけを無音化し、その前のanalyserで実出力を観測した。取得・decode・source生成・panner生成は各1/1/1/12のまま、有限値・非無音を維持した。停止後は出力ゼロ、source終了1回、破棄後は接続0・buffer参照解放・Context閉鎖を確認した。

専用Chromium全プロセス・全threadのCPU差分は5.624秒/実時間157.232秒（1 core換算平均3.577%）。AudioThreadだけの負荷ではない。JS heapは各周3.165/3.333/3.546/3.700 MB、破棄後3.174 MB、DOMは第1周以降1 document/7 nodes/2 listeners。論理PCMは7.488 MB固定。native総メモリーや数時間連続の安定性は未測定。実行環境はApple M5 Pro・15 logical CPU・24 GB、Chromium 159・Node.js 22.23.4。`node --experimental-transform-types scripts/koto-spatial-study.mjs --realtime /absolute/output` で再現し、入力hash・実音声時計・計数・CPU・heap・破棄をJSONへ記録する。
