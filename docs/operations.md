# 運用ガイド

この文書は、現行リポジトリで確認できるローカル起動、ビルド配信、仮想モニターの接続境界を扱います。追跡されているのは GitHub Actions の CI です。本番ホスト、公開ワークフロー、サービス管理、SLO、リリース切替・ロールバック手順は定義されていません。

## ローカル起動とプレビュー

ソースからの利用は[README の起動手順](../README.md#起動と操作)に従います。Vite は既定で `localhost` に開発サーバーを立ち上げ、景観アプリと仮想モニターのシグナリング API を同じオリジンで提供します。

本番用ファイルを生成し、ローカルで確認するときは次の手順を使います。

```sh
npm run build
npm exec -- vite preview
```

ビルド結果は `dist/` に出力されます。プレビューも Vite 上で動き、設定済みのシグナリング middleware を使います。プレビューを止めるときはサーバーのプロセスを終了します。より詳しいビルド確認とブラウザー検証は[検証と配布ビルド](verification.md)を参照してください。

## 静的配信とシグナリングの境界

景観アプリは `dist/` の HTML、JavaScript、`public/**` から取り込んだ素材で起動できます。仮想モニターはブラウザーから同一オリジンの `/api/virtual-monitor/` へ POST します。API の実装は [`server/virtual-monitor-signaling.mjs`](../server/virtual-monitor-signaling.mjs) にあり、[`vite.config.mjs`](../vite.config.mjs) が Vite の開発サーバーとプレビューへ登録します。画面・音声とシグナリングの役割、制約の詳細は[仮想モニター技術仕様](monitor.md)にあります。

静的ファイルだけを置くホストには、この Node.js middleware がありません。その構成で景観表示はできますが、仮想モニターのペアリングにはシグナリング API を提供するサーバーが必要です。このリポジトリには本番向け API アダプター、リバースプロキシ、外部シグナリングサービスの設定がありません。シグナリングはプロセス内メモリに状態を持ち、映像・音声は WebRTC で端末間を直接送ります。外部 STUN/TURN は使わないため、別端末同士には相互に到達できるネットワーク経路が必要です。

通常の LAN 検証では、両端末が同じ HTTPS URL を開き、ホスト名または IP に合う証明書を信頼できる必要があります。既存の具体的な手順は[別端末と VR の確認](verification.md#別端末とvr)にあります。秘密鍵と証明書はリポジトリ外に置きます。

## 環境変数

アプリ独自の `.env` ファイルや `VITE_*` 設定はありません。コードが読む `process.env` と、試験用のスイッチをまとめます。例はパスや選択値のみで、認証値を含みません。

| 名前 | 用途・範囲 | 未設定時 | 例 |
| --- | --- | --- | --- |
| `VIRTUAL_MONITOR_TLS_KEY` | Vite の LAN 検証で使う TLS 秘密鍵ファイルのパス。`VIRTUAL_MONITOR_TLS_CERT` と同時に設定します。 | 両方未設定なら TLS 証明書を読み込みません。一方だけの設定は起動時エラーです。 | `/secure/local/lumen.key` |
| `VIRTUAL_MONITOR_TLS_CERT` | 上記 TLS 鍵に対応する証明書ファイルのパス。 | 上記と同じです。 | `/secure/local/lumen.crt` |
| `COAST_CHROME_CHANNEL` | Playwright ブラウザー試験で起動するチャンネル。 | Playwright 付属 Chromium。 | `chrome` |
| `COAST_SCREENSHOTS` | 海岸・展望台とモニター試験の画像出力先。 | 画像を保存しません。 | `/tmp/lumen/coast` |
| `RESIDENCE_SCREENSHOTS` | 住戸ブラウザー試験の画像出力先。 | 画像を保存しません。 | `/tmp/lumen/residence` |
| `CINEMA_SCREENSHOTS` | 映画館ブラウザー試験の画像出力先。 | 画像を保存しません。 | `/tmp/lumen/cinema` |
| `CINEMA_AUDIO_BROWSER` | 映画館音響試験のブラウザー経路を有効にする値。`test:cinema:browser` スクリプトは `1` を設定します。 | ブラウザーチャンネルも未設定ならブラウザー経路をスキップします。 | `1` |

アセット URL は Vite が注入する `import.meta.env.BASE_URL` を参照します。[`vite.config.mjs`](../vite.config.mjs) は `base` を上書きしていません。サブパス配信はこのリポジトリで設定・検証されていません。

## 障害時の確認と復旧

| 症状 | 確認すること |
| --- | --- |
| シーンを起動できず、WebGL 2 の案内が出る | Chrome の WebGL 2 とグラフィックアクセラレーションを確認します。起動時の案内は [`src/main.ts`](../src/main.ts) にあります。 |
| 画面共有を開始できない | `getDisplayMedia()` が必要とする HTTPS または `localhost` の利用条件、ブラウザーの選択ダイアログと許可を確認します。macOS の画面・システム音声権限は[実機確認手順](verification.md#macの画面と音声)を参照します。 |
| 共有先と接続できない | 両端末の URL とネットワーク到達性を合わせ、ペアリングコードを発行後2分以内に入力します。接続中の片側が90秒応答しない場合や Vite プロセスが終了した場合はセッションを終了し、新しいコードで接続します。期限は [`virtual-monitor-signaling.mjs`](../server/virtual-monitor-signaling.mjs) に定義されています。 |
| 静的ホストで景観は開くが共有が使えない | 静的配信にはシグナリング middleware がありません。ローカル動作確認では Vite の開発サーバーまたはプレビューを使います。 |
| TLS 付き LAN 起動に失敗する | 鍵と証明書の両パスを設定し、両端末が証明書の発行元を信頼し、指定ホスト名または IP と証明書が一致していることを確認します。鍵と証明書はプロジェクト外に置きます。 |

シグナリングのセッションとレート制限状態はプロセスメモリ内です。Vite を再起動すると現在の共有セッションは失われ、以前のコードを復旧できません。サーバーを通常停止して起動し直し、必要な端末を新しいコードでペアリングしてください。永続化された利用者データやセッションデータはこの構成にありません。

本番リリース先と前版アーティファクトの保管先が定義されていないため、ホスト固有のロールバック手順はここでは確定できません。現在の GitHub Actions は CI のみで、デプロイやリリースは行いません。

## 確認範囲

ブラウザー試験と実機確認の手順・条件は[検証と配布ビルド](verification.md)を正本とします。自動の仮想モニター試験は合成した画面・音声と模擬入力を使うため、OS の画面選択ダイアログ、実機音声経路、ヘッドセットの挙動を証明しません。文書にある macOS、別端末、VR の手順は個別の実機確認項目です。手順が記載されていること自体は、実機確認の実施記録ではありません。Windows の取得・音声・PCVRは未検証と記録されています。他ブラウザーの対応範囲も定義されていません。
