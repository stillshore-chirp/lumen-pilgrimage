## Issue・PRの記載

[Issueテンプレート](../.github/ISSUE_TEMPLATE/change.md) に、依頼、確認した事実、実装側の判断と受け入れ条件を記載します。途中で判断や範囲を変えた場合は、理由と受け入れ条件への影響をIssueのコメントに残し、本文を更新します。

[PRテンプレート](../.github/pull_request_template.md) に、関連Issueと、最終差分で確認した条件・結果・証拠を記載します。検証結果をまとめるときは対象のコミットを照合し、未実施・未確認の項目と理由、受け入れへの影響も記録します。景観・音響・操作の変更では、該当する証拠をPRから参照できるようにしてください。

| 対象 | 記録する条件と証拠の例 |
| --- | --- |
| 景観 | 視点・時刻・描画設定をそろえた変更前後の画像 |
| 音響 | 場所・時刻・音量設定をそろえた録音や測定値 |
| 操作 | 起点・ブラウザや入力機器・手順と、ブラウザ試験や手動確認の結果 |

素材を公開できない場合は、確認条件と結果を公開できる範囲で記載します。

## 更新と検証

文書や参照を変更したら `npm run validate:harness` を実行します。[静的検査](../scripts/validate-harness.mjs) は現行文書の Markdown インラインリンクと、記載された npm スクリプト名を確認します。[旧ゲームの計画と進捗](../plans/README.md#旧ゲームの履歴) は作成当時の記録です。
