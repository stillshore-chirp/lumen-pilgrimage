# 70階住戸図面の再生成

[現行図面](../residence-70f-drawings.pdf)は、保存した既存PDFへ、[共通の住戸設計データ](../../../src/coast/world/residence/residencePlan.ts)から読み取った改訂をベクトルで加えたものです。設計の意味と利用条件は[住戸の設計仕様](../residence-70f-design.md)を参照してください。

## 入力と来歴

| 入力 | 役割・確認方法 |
| --- | --- |
| [保存した改訂前PDF](residence-70f-drawings-baseline.pdf) | `eca7905` で更新されたA3横4ページ、171,100 bytes。元の家具・寸法・眺望断面・街区図などを保持する入力です。現行設計を示す配布用PDFではありません。SHA-256は `65d67fc8789d522c2b4d92a5d8bf4ec64ab41bbd890878747f13c50fab0fb635`。 |
| [改訂仕様](residence-70f-revisions.json) | 入力ハッシュ、座標変換、改訂前の終点、注記位置、書体・生成ツールの版を固定します。 |
| [改訂スクリプト](../../../scripts/revise-residence-drawings.py) | 共通設計データの壁・建具・低天井・吊点・高さを読み取り、PDFの該当ページを更新します。 |
| Arial Unicode MS | 改訂前PDFと同じ書体を使い、追加注記の必要な文字だけを埋め込みます。書体ファイルは同梱しません。入力のSHA-256とOpenType `OS/2.fsType=8`を検査します。 |

既存の作業ツリーと既存PDFの更新コミットに、元の編集用図面・生成スクリプトは見つかりませんでした。この処理は元の作図原稿を復元したものではなく、既存PDFの来歴と改訂処理を保存する方式です。元図の全ページを自由に再作図する機能は持ちません。

### 書体の確認範囲

2026年11月28日の生成では、macOS 27.2の既存書体 `/System/Library/Fonts/Supplemental/Arial Unicode.ttf` を利用しました。内部名 `Arial Unicode MS`・`Version 1.01x` は保存PDFの2つの埋込サブセットと一致し、その2つのサブセットのハッシュも改訂後に保持します。改訂仕様の書体ハッシュは今回の完全な書体ファイルを固定する値です。旧作図時の完全な書体ファイルは未追跡のため、それとのハッシュ一致は証明しません。

[AppleのmacOSライセンス §2.E、英語版P3](https://www.apple.com/legal/sla/docs/macOSGoldenGate.pdf)は、同梱書体の埋込を付属する埋込制限が認める場合に限っています。[OpenType `OS/2.fsType`](https://learn.microsoft.com/en-us/typography/opentype/spec/os2#fstype)の値8は編集可能な文書埋込を表します。入力と追加PDFサブセットが値8を保持し、サブセット禁止・ビットマップ限定ビットがないことを検査しました。[MicrosoftのFAQ「Document embedding」「Other fonts」](https://learn.microsoft.com/en-us/typography/fonts/font-faq#document-embedding)も文書埋込と書体本体の再配布を区別しますが、適用対象はWindows同梱書体です。このFAQ単独をmacOSの許諾とは扱いません。

確認できる入手来歴は保護されたシステム領域の既存ファイルと内部情報までで、OS・書体の購入・導入履歴や個別契約は未監査です。埋込フラグだけを完全な許諾証明とは扱いません。今回の利用は文書の必要文字のPDF内埋込に限り、書体本体の同梱・Webフォント化・ゲーム内フォント配布は行いません。

## 座標と改訂範囲

共通設計データの単位はm、南西原点から東をE正、北をN正とします。PDF座標は左下原点のptです。縮尺分母を `s` とすると、換算係数は `1000 × 72 ÷ 25.4 ÷ s` pt/mです。保存PDFの壁芯と既存の外周寸法から、次の対応を確認しています。

| ページ | PDF上の基準点 | 換算係数 | 改訂内容 |
| --- | --- | --- | --- |
| P1 平面図、1:100 | `(E=0,N=0)` → `(76.53543,144.5669)` pt | 28.34645669 pt/m | N9.95の壁をE19.00からE22.80まで延長。厚さ0.14 m。寝室02の見出しと面積表記だけを南へ0.15 m移して壁との接触を避けます。室の外形・面積と既存の出入口は維持します。 |
| P4 茶室詳細平面、1:30 | `(E=3.65,N=0)` → `(121.8898,236.6929)` pt | 94.48818898 pt/m | 既存6部材の外形包絡を破線で表示。4吊点を円、内向き斜材を破線の平面投影で示し、板・梁・主天井・床スラブの高さを注記します。既存の畳・家具・障子・寸法は保持します。 |
| P2・P3 | 変更なし | 元図の縮尺 | 既存ページの内容ストリームと見た目を保持します。 |

P4は詳細平面に上方部材を重ねた投影図です。部材の高さ・吊支持の連続は、注記と共通設計データを併せて読みます。4吊点・金物・斜材は仮想空間の制作上の寸法であり、実建築の構造安全性・耐力・法適合を示す図面ではありません。印刷時は「実際のサイズ」を選び、用紙に合わせた拡大縮小をしない場合に記載縮尺となります。

## 生成と照合

Python 3.12、`reportlab==4.4.9`、`pypdf==6.21.4` が必要です。既存の任意の素材作成環境で実行し、ブラウザーやアプリの通常依存には追加しません。書体の既定位置はmacOSの `/Library/Fonts/Arial Unicode.ttf` です。同じハッシュの書体を別の位置に置く場合は `--font /path/to/Arial-Unicode.ttf` を指定します。

リポジトリのルートで実行します。

```bash
python3 scripts/revise-residence-drawings.py
python3 scripts/revise-residence-drawings.py --check
```

改訂仕様の `activeRevisionIds` で適用を明示します。`teaSupport` はP4の低天井と吊支持、`partition` はP1の寝室間仕切りと表記位置の改訂です。未知・重複・空のID指定は拒否します。有効な改訂だけのPlan宣言とページを処理し、選択していないページは保存PDFのまま保持します。共通設計データの完全なファイルハッシュは、改訂の組合せごとに固定します。

この版の有効IDは `teaSupport` と `partition` です。P1・P4を改訂し、P2・P3を保持します。

生成は既存PDFへ追記を繰り返す方式ではありません。毎回保存した入力PDFから開始するため、改訂が重複しません。`--output /path/to/review.pdf` で別ファイルへ出力できます。`--check` は書き込まず、再生成したバイト列と対象ファイルの完全一致を検査します。日時メタデータは再現性のため固定値であり、作成実日時を示しません。

入力PDF・共通設計データ・書体のハッシュ、生成ライブラリの版、想定した宣言形式、改訂対象の既存文字位置が異なる場合は失敗します。共通設計データを変更した場合は、差分・図面への影響・座標の対応を確認してから改訂仕様を更新してください。ハッシュだけを置き換えて図面の一致を仮定しないでください。

PDFを更新したら、Popplerで全4ページを同じ解像度のPNGへ描画し、P1の壁接合・建具・室名、P4の投影と高さ・文字の可読性、P2・P3の同一性を目視と画像差分で照合します。

```bash
pdftoppm -r 150 -png docs/residence/residence-70f-drawings.pdf /tmp/residence-70f
pdfinfo docs/residence/residence-70f-drawings.pdf
```

ページ数・用紙寸法・文字抽出も確認します。再生成の一致は入力と出力の再現性を示すもので、3Dの実形状・移動・音響・支持の描画の検証を代替しません。対応する実出力の評価は[住戸の設計仕様](../residence-70f-design.md)と[検証ガイド](../../verification.md)から参照します。
