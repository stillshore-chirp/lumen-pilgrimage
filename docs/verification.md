# 検証と配布ビルド

依存関係は [README の起動手順](../README.md#起動と操作) に沿って用意します。変更時に必要な共通ゲートは [AGENTS.md](../AGENTS.md#検証)、文書変更の受け入れ条件は [文書の責務と更新基準](documentation-structure.md#更新と受け入れ) を参照してください。

## ゲートの選び方

| 変更範囲 | 実行するゲート | 確認できること |
| --- | --- | --- |
| 文書と参照だけ | `npm run validate:harness` | 現行文書と素材クレジットのリポジトリ内リンク、記載した npm スクリプト名、README からの到達可能性を検査します。内容の正確さや実機での動作は証明しません。 |
| アプリのコード | `npm run check` | 型チェック、本番ビルド、文書リンク検査、探索・モニター・住戸・映画館の Node テストをまとめて実行します。CI もこのコマンドを使います。 |
| 探索、移動、描画、音響、ワールド遷移 | `npm run check` の後に `npm run test:coast:browser` | ビルドしたアプリの操作・描画・音響・時間帯引き継ぎをブラウザーで確認します。 |
| 仮想モニター | `npm run check` の後に `npm run test:monitor:browser` | 別タブの接続、合成メディアの伝送、表示・配置・音量経路をブラウザーで確認します。OSの画面選択ダイアログは試験用に置き換えます。 |
| 住戸または映画館 | `npm run check` の後に `npm run test:residence:browser` または `npm run test:cinema:browser` | 該当ワールドの画面操作とブラウザー描画を確認します。物理ディスプレイ、スピーカー、VR機器の出力品質は実機で別に確認します。 |

`npm run check` はローカルと CI のコードゲートです。ブラウザー試験と実機の画面共有・入力・音響は、それぞれ別の確認です。`validate:harness` は維持対象の各文書を README から辿れることも検査します。

## 一括検証

```sh
npm run check
```

型チェック、本番ビルド、ハーネス文書の静的検査、探索の回帰テストと仮想モニターの単体・統合テストを実行します。[CI](../.github/workflows/ci.yml) でも同じコマンドを実行します。

- `npm run build` は型チェックと Vite の本番ビルドを行います。
- `npm run validate:harness` は現行文書のリポジトリ内リンクと、記載された npm スクリプト名を確認します。
- `npm run test:coast` は探索の移動・地形・音響と、海岸の休憩所4か所でベンチを通過する歩行を検証します。
- `npm run test:monitor` はシグナリングの承認・期限・権限、共有と切断、画面取得の報告、映像面の配置、WebXRの模擬入力、音声ミキサーを検証します。
- `npm run test:cinema` は客席数と通路、着地点、幕の光量・室内反射、客席で変わる音の経路と残響を検証します。
- `npm run test:residence` は寝室3室・茶室・書斎への経路、室内家具の通過、窓・引戸・手すりの歩行判定、音源の距離・壁・戸による減衰を検証します。軽量・高品質の昼夜で街区と共有都市の描画形状を調べ、住戸の脇を通る幹線の舗装、外周の先での交差点への接続、車道や通りの先の見通しへの建物・基壇の張り出しを確認します。

## 配布ビルドの確認

`dist/` のローカル確認には、ビルド後に `npm exec -- vite preview` を使います。

## ブラウザでの回帰テスト

ブラウザー試験は、`dist/` を Vite のプレビューサーバーから開くため、実行前に `npm run build` を完了させます。`COAST_CHROME_CHANNEL=chrome` はインストール済みの Chrome を選びます。Playwright 付属の Chromium を使う場合は、必要に応じて `npx playwright install chromium --no-shell` を一度実行します。各試験は Playwright で自動操作し、実機の入力機器や音響機器は使いません。インストール済み Chrome で描画や操作の待機がタイムアウトする場合は、Playwright が指定する Chromium でも条件をそろえて確認できます。

景観探索のブラウザテストはビルド後に MacBook の Google Chrome で `COAST_CHROME_CHANNEL=chrome npm run test:coast:browser` を実行します。Playwright の Chromium を使う場合は、次のコマンドで準備と実行ができます。

```sh
npx playwright install chromium --no-shell
npm run test:coast:browser
```

ブラウザテストは、海岸と丘陵展望台の描画・音響・移動と時間帯の引き継ぎを確認します。足音は住戸と映画館も含めた全4ワールドで、歩行時の Web Audio 出力、静止・飛行時の発音停止、環境音との独立したオン・オフ、0% での消音を確認します。展望台ではデッキ、外周の石畳、階段で使われる音も比較します。全体・種類別音量のワールド間の保持、コンテキスト中断からの再開、音量スライダーの視野角との整列と狭い画面での収まりも検証します。音声の開始待ちにオフへ切り替える操作、模擬した自動再生制限下の再開、模擬したBFCache復帰通知による音量とオン・オフの再適用も確認します。

直接起動時は、フォーカス通知とフォーカス状態の反映の順を変え、環境音をオンにする前に `W` `A` `S` `D` で視点が動くことを確認します。林の休憩所と展望台のベンチは歩いて通過し、展望台の階段と手すりも確認します。夜の展望台では前方の地上の虫の信号を計測し、昼に戻すと静まることを検証します。過去の直接起動 URL で開いた場合も自然景観探索が起動することを確認します。

`COAST_SCREENSHOTS` に画像の出力先を指定すると、潮だまり沿いの東散策路を歩いて、棚滝の同じ位置を昼夜で撮影できます。昼は飛沫と虹の位置、夜は色帯が消えることを見比べます。

ワールド照明は、海岸・展望台・住戸・映画館のブラウザー試験で、同じ時刻・視点で点灯前後の描画を比較します。住戸では区画・器具の状態と「既定」での復帰、映画館では場内灯の切り替えと上映・清掃・非常点検の共存も確認します。

住戸はビルド後に `COAST_CHROME_CHANNEL=chrome npm run test:residence:browser` で確認します。直接起動の移動とソファの通過、ジャンプと飛行からの着地、飛行中の居間の天井と窓の停止、南窓の昼夜と描画切替、ワールド間移動、主寝室からバルコニーへの往復、手すりと引戸開閉時の Web Audio の信号変化を確認します。`RESIDENCE_SCREENSHOTS` に出力先を指定すると、窓辺とバルコニーの描画に加え、検証用ページでソファ位置・眼高1.15 mからの眺望を記録します。座位の撮影は縦視野角60°で、下向き17°と、足元側も含めた下向き24°を使います。

「メニュー」から「住戸の遠隔操作」を開き、照明・カーテン・家電と水栓の切り替えで外枠の寸法と位置がそろうことを、通常の画面、幅の狭い画面、幅と高さの小さい画面で確認します。高さの小さい画面では、選択中の一覧を末尾までスクロールしたときに最後の設備とカテゴリボタン、「閉じる」が画面に残ることを確認します。キーボードで一覧末尾の設備を開く操作、一覧に戻ったときのフォーカス、非選択の設備一覧が操作対象から外れることも確認します。

夜の南窓と東窓では、同じ画角で少しずつ視点を振ります。軽量・高品質の両方で街の画素の急な明暗変動を計測し、窓明かりが見える輝度も確認します。

仮想モニターの通し試験はビルド後に `COAST_CHROME_CHANNEL=chrome npm run test:monitor:browser` で実行します。別のブラウザコンテキスト間のWebRTC接続、承認、映像面の描画、音声波形、音量と描画品質の独立性、配置操作、停止と解放を検証します。ワールド間移動では、住戸のテレビと映画館スクリーンからの浮遊表示への切り替え、履歴移動、読み込み失敗・競合、同じ WebRTC 接続とメディアでの再生継続を検証します。WebXR セッションを模擬し、移動中の描画ループと VR 終了後のデスクトップ描画の復帰も確認します。描画パターンと合成音からブラウザーのメディアトラックを生成し、テスト側で `getDisplayMedia()` の画面選択を差し替えます。OSの実画面取得やシステム音声経路はこの試験の対象外です。`npm run test:monitor` のWebXR入力試験も模擬セッションで実行します。

住戸の仮想モニターでは、テレビと浮遊表示の両方で、遠隔操作パネルと現地スイッチからリビング・ダイニングの照明を一括で切り替えます。パネルの開閉、映像面の非表示と再表示、時間帯・描画品質の変更、模擬した BFCache の保持・復帰通知を通じて、元の WebRTC 接続、受信ストリームとトラック、映像フレーム、音声波形が続くことを確認します。別の試験で配信側と視聴側の poll に一時障害を起こし、接続の維持、共有停止、再ペアリング、切断時の解放を確認します。BFCache の試験は保持・復帰通知を模擬します。実際にブラウザーがページをキャッシュする条件は端末とブラウザーに依存します。

配信音声の出力先は、サーバーが設定を反映した直後に応答だけを失わせて確認します。配信側のトラックの送出を先に切り替え、反映中に選んだ最新の設定が視聴側へ届くまで同じ接続で映像が続くことを確認します。設定の再送を待っている間に共有を停止できることも検証します。単体試験では、遅れて届いた旧音声設定が反映済みの値と生存確認の期限を更新しないことを確認します。模擬時計でシグナリング停止中の同一接続での復帰と、承認または生存確認の期限に達したときのメディア解放を確認します。

「モニター音声」を同じボタンでオン→オフ→オンと切り替え、共有音声の波形と押下状態を検証します。音声なしと「PC側のみ」での停止表示、出力先を「両方」に戻したときの再開、ワールド間でのオン・オフの引き継ぎ、再接続時の初期状態も確認します。ブラウザーの再生開始を保留・拒否させて再試行を確認し、保留中に取り消したときはブラウザーが遅れて再開しても無音を保つことを測定します。

映画館の [配置テスト](../scripts/cinema-navigation.test.mjs) は、通常席の眼高1.15 mと車いす席の眼高1.00 mから幕の下端へ線を引き、前列の背もたれと床上1.30 mの頭頂モデルを越えることを確認します。頭頂モデルの高さに対する最小余裕は2 cmです。座位から見て手すりと支柱が幕に重ならないこと、段数、踏面26 cm以上とけあげ18 cm以下、横通路と車いすスペースの高さ、8か所の扉との接続も検証します。

映画館はビルド後に `COAST_CHROME_CHANNEL=chrome npm run test:cinema:browser` で確認します。`--no-shell` で導入した Chromium を使う場合は、`COAST_CHROME_CHANNEL=chromium npm run test:cinema:browser` を実行してください。音響試験はチャンネル未指定時に Chromium のヘッドレスシェルを使います。

座位の初期位置から移動し、客席の段床と着地点、ジャンプと座席背面を越える飛行、飛行中の天井の停止、非常口の閉じた境界、ファストトラベルでの入り江往復、照明と試映の制御を確認します。ChromeのOfflineAudioContextで直接音・残響の波形、席間と品質間の音量差を測ります。`CINEMA_SCREENSHOTS` にディレクトリを指定すると中段中央・後方側席・車いす席からの画面と、上映時・清掃時の場内を撮影します。

暗転の比較では「上映」を選び、「仮想モニター」の「投影を止める」が「スクリーンに映す」に変わったことと、試映が停止中であることを確認します。暗転の切り替えが終わった後、後方側席（R20）の同じ画角で軽量と高品質を撮り、天井と客席の残光、出口表示と段鼻の受光を画素値で確認します。画素値はブラウザーの描画結果です。実機での見え方と物理的な照度・輝度は実機で確認します。

仮想モニターの通し試験では、映画館の幕に横長と縦長の共有映像を映します。前方の床に映る反射光の色が映像に合わせて左右で入れ替わり、黒いフレームで弱まることを画素値で確認します。接続したまま投影を止めると反射が消え、同じ映像を再表示すると反射が戻ることも検証します。非常点検時の映写・音声停止、共有終了も確認します。

## 実機での確認

ゲームパッドの両スティックと上下・モード切替を試します。ヘッドホンでは滝との距離や視点を変え、定位と音割れ・途切れの有無を確認します。

足音は「種類別の音量」で歩行音をオンにし、環境音をオフにして確認します。同じ音量設定で、海岸の浜、丘陵展望台のデッキ・外周の石畳・東階段、住戸の木床とタイル、映画館の絨毯通路と段を歩きます。足音が足元から鳴り、材質によって着地と擦れの聞こえ方が変わります。立ち止まる、飛行する、歩行音をオフにする、歩行音を 0% にする各操作で足音が続かないことを確認します。音量とオン・オフは移動先の「種類別の音量」で確認します。

住戸の音を実機で確認するには、ヘッドホンで主寝室に入り、環境音をオンにして戸を閉めたまま聞きます。次に `E` で開けてバルコニーへ進み、南と東で音の方向が変わることを確認します。夜に切り替え、交通の間隔と室内外の音量差も聞き比べます。

## 仮想モニターの実機確認

映画館を実機で確認する場合は、`?world=cinema` で起動して中段、前方、後方の席を順に選びます。タブを共有し、画面の白いフレームと同期するクリック音を再生します。ステレオ出力と映画館の空間音響で、同じ機材を使って追加遅延を比較します。VRでは首を振って幕と音源の方向が一致するかを確認し、暗転時の段鼻や出口の視認性と、明暗の切り替え時のちらつきを個別に記録します。実機の耳元音圧と表示輝度は較正した機器で確認します。

### Macの画面と音声

1. `npm run dev` で起動し、Chromeの2タブで同一のローカルURLを使います。[操作の手順](exploration.md#仮想モニター) に沿って、開発用のウィンドウを一つ選択してペアリングします。ウィンドウ内でスクロールし、景観内の映像が更新されるか確認します。「共有を停止」で映像が消え、再接続案内が出ることも確認します。
2. Chromeが画面を取得できない場合は、macOSの「システム設定」→「プライバシーとセキュリティ」→「画面収録とシステムオーディオ録音」でChromeの許可を確認します。初回はChromeが再起動を求める場合があります。[Appleの画面収録の設定](https://support.apple.com/ja-jp/guide/mac-help/mchld6aa7d23/mac)
3. 音の出るテスト用Chromeタブを共有し、選択画面で音声共有を有効にします。視聴側の「モニター音声」で聞こえ方が切り替わることを確認します。オンにした状態で配信側を「両方」「PC側のみ」に切り替え、視聴側の出力を聞きます。「VR側のみ」は対応するタブを選び直し、PC側と視聴側を別々に聞きます。ウィンドウや画面全体の音声は、同じダイアログが音声共有を提示した場合に試します。

自動テストでは合成メディアでの伝送・描画・音声切替を確認できます。macOSの実画面選択とOSの音声経路には、対話型の共有ダイアログと利用者の許可が必要です。

### 別端末とVR

信頼済みLAN内で視聴端末と配信端末から同じHTTPS URLを開きます。サーバーに指定する名前またはIPと一致する証明書を用意し、両端末で発行元を信頼できる状態にします。秘密鍵と証明書はリポジトリ外に置きます。

```sh
npm run build
VIRTUAL_MONITOR_TLS_KEY=/path/to/lumen.key VIRTUAL_MONITOR_TLS_CERT=/path/to/lumen.crt npm exec -- vite preview --host 192.168.1.20
```

`192.168.1.20` をサーバーのLANアドレスに置き換え、表示されたポートを使って接続します。開発サーバーなら同じ環境変数で `npm run dev -- --host 192.168.1.20` を使えます。シグナリングにはこのViteサーバーが必要です。 `dist/` の静的配布では景観探索を起動できます。別端末同士の通信には、LANで相互に到達できることも必要です。[Viteのプレビュー設定](https://vite.dev/config/preview-options)

視聴端末で上の手順どおり映像と音声を用意し、「VRで見る」を選択します。Touch系のグリップ、手のピンチ、両手の拡縮をそれぞれ試し、手を離すと固定されるか確認します。頭を回し、ステレオと空間音響で音の向きが変わる条件を比較します。ヘッドセットが画面キャプチャを提供する必要はありません。確認済みのVR入力はモックによるもので、ヘッドセットと別端末間の実接続は実機で確認してください。

### Windowsを配信元にする

LAN上の配信ページをWindowsのChromeで開き、同じコードで視聴先に接続します。Windowsでテスト用ウィンドウと画面全体をそれぞれ選び、入力した映像と音声が届くかを確認します。音声の有無は共有ダイアログと返されたトラックに従います。Windows機での取得・音声・PCVRは未検証です。
