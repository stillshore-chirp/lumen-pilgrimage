# 検証と配布ビルド

依存関係は [README の起動手順](../README.md#起動と操作) に沿って用意します。変更時に必要な検証は [AGENTS.md](../AGENTS.md#検証) を参照してください。

## 一括検証

```sh
npm run check
```

型チェック、本番ビルド、ハーネス文書の静的検査、探索の回帰テストと仮想モニターの単体・統合テストを実行します。[CI](../.github/workflows/ci.yml) でも同じコマンドを実行します。

- `npm run build` は型チェックと Vite の本番ビルドを行います。
- `npm run validate:harness` は現行文書のリポジトリ内リンクと、記載された npm スクリプト名を確認します。
- `npm run test:coast` は探索の移動・地形・音響の単体テストを実行します。
- `npm run test:monitor` はシグナリングの承認・期限・権限、共有と切断、画面取得の報告、映像面の配置、WebXRの模擬入力、音声ミキサーを検証します。

## 配布ビルドの確認

`dist/` のローカル確認には、ビルド後に `npm exec -- vite preview` を使います。

## ブラウザでの回帰テスト

景観探索のブラウザテストはビルド後に MacBook の Google Chrome で `COAST_CHROME_CHANNEL=chrome npm run test:coast:browser` を実行します。Playwright の Chromium を使う場合は、次のコマンドで準備と実行ができます。

```sh
npx playwright install chromium --no-shell
npm run test:coast:browser
```

ブラウザテストは、海岸と丘陵展望台の描画、移動・遊泳・飛行、模擬ゲームパッド入力、環境音、描画品質、ワールド間移動と時間帯の引き継ぎを確認します。展望台では環境音の開始とミュート、2階への階段の往復、手すりでの停止、夜のファストトラベルも検証します。過去の直接起動 URL で開いた場合も自然景観探索が起動することを確認します。

仮想モニターの通し試験はビルド後に `COAST_CHROME_CHANNEL=chrome npm run test:monitor:browser` で実行します。別のブラウザコンテキスト間でのWebRTC接続、承認、実際の映像面の画素、音声波形、音量と描画品質の独立性、配置操作、停止と解放を検証します。キャプチャ元には描画パターンと合成音を使います。画面取得の模擬はテスト側に限定します。

## 実機での確認

ゲームパッドの両スティックと上下・モード切替を試します。ヘッドホンでは滝との距離や視点を変え、定位と音割れ・途切れの有無を確認します。

## 仮想モニターの実機確認

### Macの画面と音声

1. `npm run dev` で起動し、Chromeの2タブで同一のローカルURLを使います。[操作の手順](exploration.md#仮想モニター) に沿って、開発用のウィンドウを一つ選択してペアリングします。ウィンドウ内でスクロールし、景観内の映像が更新されるか確認します。「共有を停止」で映像が消え、再接続案内が出ることも確認します。
2. Chromeが画面を取得できない場合は、macOSの「システム設定」→「プライバシーとセキュリティ」→「画面収録とシステムオーディオ録音」でChromeの許可を確認します。初回はChromeが再起動を求める場合があります。[Appleの画面収録の設定](https://support.apple.com/ja-jp/guide/mac-help/mchld6aa7d23/mac)
3. 音の出るテスト用Chromeタブを共有し、選択画面で音声共有を有効にします。「両方」「PC側のみ」では視聴側の出力が変わることを確認します。「VR側のみ」は対応するタブを選び直し、PC側と視聴側を別々に聞きます。ウィンドウや画面全体の音声は、同じダイアログが音声共有を提示した場合に試します。

自動テストでは合成メディアでの伝送・描画・音声切替を確認できます。macOSの実画面選択とOSの音声経路には、対話型の共有ダイアログと利用者の許可が必要です。

### 別端末とVR

信頼済みLAN内で視聴端末と配信端末から同じHTTPS URLを開きます。サーバーに指定する名前またはIPと一致する証明書を用意し、両端末で発行元を信頼できる状態にします。秘密鍵と証明書はリポジトリ外に置きます。

```sh
npm run build
VIRTUAL_MONITOR_TLS_KEY=/path/to/lumen.key VIRTUAL_MONITOR_TLS_CERT=/path/to/lumen.crt npm exec -- vite preview --host 192.168.1.20
```

`192.168.1.20` をサーバーのLANアドレスに置き換え、表示されたポートを使って接続します。開発サーバーなら同じ環境変数で `npm run dev -- --host 192.168.1.20` を使えます。シグナリングにはこのViteサーバーが必要です。 `dist/` の静的配布では景観探索を起動できます。別端末同士の通信には、LANで相互に到達できることも必要です。[Viteのプレビュー設定](https://vite.dev/config/preview-options)

視聴端末で上の手順どおり映像と音声を用意し、「VRで見る」を選択します。Touch系のグリップ、手のピンチ、両手の拡縮をそれぞれ試し、手を離すと固定されるか確認します。頭を回し、ステレオと空間音響で音の向きが変わる条件を比較します。ヘッドセットが画面キャプチャを提供する必要はありません。確認済みのVR入力はモックによるもので、ヘッドセットと別端末間の実接続は実機で確認してください。

### Windowsを配信元にする

LAN上の配信ページをWindowsのChromeで開き、同じコードで視聴先に接続します。Windowsでテスト用ウィンドウと画面全体をそれぞれ選び、入力した映像と音声が届くかを確認します。音声の有無は共有ダイアログと返されたトラックに従います。Windows機での取得・音声・PCVRは未検証です。
