# 作業計画

## 目的と対象範囲

実現する結果と変更範囲を記載する。範囲の判断に関係する前提や対象外の項目があれば添える。

## 関連分野と根拠

[必須の専門工程](../docs/agent-harness.md#専門分野の業務工程)に沿って、関連分野・相互作用、品質に影響する生成から体験までの工程、再利用する調査と追加の不確実性を記す。要求から原典・モデル・仮定、設計/制作/実装、検証までの対応は正本に置いて参照する。外部採用がある場合は、候補比較と利用・改変・配布の権利条件の照合先も添える。

## 受け入れ条件

- [ ] 利用者が確認できる振る舞い、または成果物が満たす条件を記載する。

制作前に、対象の品質・妥当性・性能・権利・保守性に必要な評価軸と判定基準を定める。チェックだけで達成にせず、成果物と実結果の参照を残す。

## 検証

実行するコマンドまたは手動操作と、期待する結果を記載する。リポジトリのコマンドは [検証と配布ビルド](../docs/verification.md) を参照する。実施後は結果を記録し、確認できない項目があれば理由を添える。

| 条件 | 入力・機器/環境・観察/測定方法・判定基準 | 成果物と実結果の参照 | 未達・未検証と次の対応/解消条件 |
| --- | --- | --- | --- |
| | | | |

計算・模擬・実測・実機・知覚評価の確認範囲を分ける。必須の未検証は保持し、独立して実行できる工程を続ける。[段階判定](../docs/agent-harness.md#進行段階の確認)で原典から実結果までを照合してレビュー・完了を判断する。

## 作業上の判断

依存関係、受け入れ条件の変更、データ移行や切り戻しなど、引き継ぎに必要な判断がある場合に記載する。
